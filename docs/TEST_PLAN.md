# План Тестування (Test Plan) & Demo QA Checklist

**Відповідальний:** ЖЕ (Team Lead + QA)

---

## 1. Рівень 1: Тестування API (Postman / docs/test_endpoints.ps1)

### 1.1 Статуси та валідація ендпоінтів
- [ ] `POST /api/auth/register` — успішна реєстрація (`201`) та обробка зайнятого email (`400`).
- [ ] `POST /api/auth/login` — успішний вхід (`200`), повернення валідного JWT токена.
- [ ] `GET /api/meta/dota` — повертає `200`, статус патчу (напр. `7.37d`), масив `meta_heroes` з полями `tier`, `win_rate`, `pick_rate`, `ai_summary`.
- [ ] `GET /api/dota/heroes/14` (Pudge) — повертає `200`, здібності героя (`abilities`) та згенерований `ai_build` (тактика, послідовність прокачки, айтеми).
- [ ] `GET /api/dota/heroes/99999` — повертає `404 Not Found`.
- [ ] `POST /admin/sync` — повертає `200` і запускає оновлення даних з OpenDota / Claude. Захищений Bearer токеном.

### 1.2 Формат даних і зображень
- [ ] Усі аватари (`avatar_url`) та іконки здібностей (`icon_url`) відкриваються без 404 помилок.
- [ ] Відсутні `null` у полях назви героїв, здібностей та AI-білдів.

---

## 2. Рівень 2: Мобільний інтерфейс (Flutter UI/UX)

- [ ] **Splash Screen:** Швидкий запуск, немає білого порожнього екрана.
- [ ] **Головний екран мети:** Список героїв з сортуванням за Tier (S, A, B), показ вінрейтів.
- [ ] **Індикатор часу:** Працює напис «Оновлено X хв тому».
- [ ] **Картка героя:** Всі блоки здібностей та AI-рекомендацій поміщаються на екрані без помилок переповнення (RenderFlex overflow).
- [ ] **Стани завантаження:** Під час запитів до сервера відображається Skeleton / CircularProgressIndicator.

---

## 3. Рівень 3: Відмовостійкість (Offline & Fallback)

- [ ] **Режим польоту:** При вимкненні інтернету Flutter бере останні дані з Hive-кешу.
- [ ] **Падіння OpenDota / Claude API:** Бекенд не повертає 500, а віддає резервний знімок `meta.json`.

## 4. Фінальний Demo Checklist перед суддями

- [ ] Бекенд запущений (локально чи на Render/Railway) і відповідає на `/api/meta/dota`.
