# 🎮 GameGuide Mobile

Мобільний інтерактивний довідник з кіберспортивних та комп'ютерних ігор (Dota 2, Counter-Strike 2 тощо).  
Проєкт розроблено в рамках хакатону.

---

## 👥 Команда та розподіл ролей

- **Team Lead & QA / Тестувальник:** Загальна архітектура, контроль стандартів розробки, Git-процеси, тестування API та клієнта, фінальний реліз і демо.
- **Backend (API & Business Logic):** Розробка REST API, валідація, бізнес-логіка, інтеграція зі Swagger/OpenAPI.
- **Backend (Database):** Проєктування схем БД, оптимізація індексів, підготовка сід-даних (Dota 2 / CS2), міграції.
- **Frontend (Mobile):** Кросплатформений мобільний застосунок, UI/UX, інтеграція з API, кешування та підтримка офлайн-режиму.

---

## 🏗️ Архітектура та структура репозиторію

Репозиторій організовано за монорепо-структурою для швидкої синхронізації та уникнення конфліктів у Git:

```text
hakatone/
├── backend/                  # Серверна частина
│   ├── database/             # База даних
│   │   ├── schema.sql        # Схема створення таблиць (PostgreSQL / SQLite)
│   │   └── seeds/            # Готові тестові дані (dota2.json, cs2.json)
│   └── README.md             # Інструкції для Backend-розробника
├── mobile/                   # Клієнтська мобільна частина
│   └── README.md             # Інструкції для Mobile-розробника
├── docs/                     # Проєктна документація
│   ├── openapi.yaml          # Єдиний контракт API (OpenAPI 3.0)
│   ├── DATABASE_ERD.md       # Діаграма бази даних (Mermaid ERD)
│   └── TEST_PLAN.md          # Чекліст тестування для QA
├── .gitignore                # Фільтр для Dart/Flutter, Node.js, Python, IDE
└── README.md                 # Загальний опис проєкту
```

---

## ⚡ Швидкий старт для кожного учасника

1. **Мобільному розробнику:** Почніть з вивчення [mobile/README.md](mobile/README.md). Ви вже маєте готові мокові дані в [backend/database/seeds](backend/database/seeds/) і можете верстати екрани прямо зараз!
2. **Розробнику БД:** Ознайомтеся з [docs/DATABASE_ERD.md](docs/DATABASE_ERD.md) та застосуйте [backend/database/schema.sql](backend/database/schema.sql).
3. **Бекенд-розробнику:** Ваш контракт описано в [docs/openapi.yaml](docs/openapi.yaml). Усі ендпоінти узгоджені з мобільним додатком.
4. **Тестувальнику / Тімліду:** Використовуйте [docs/TEST_PLAN.md](docs/TEST_PLAN.md) для контролю готовності до пітчингу.

## 🌿 Git Workflow

1. Основна гілка: `main` (завжди стабільна, готова для презентації).
2. Робоча інтеграційна гілка: `dev`.
3. Фічі розробляються в окремих гілках:
   - `feature/mobile-catalog-ui`
   - `feature/backend-games-api`
   - `feature/db-seeds-init`
4. Злиття тільки через Pull Request після перевірки Тімлідом/QA.
